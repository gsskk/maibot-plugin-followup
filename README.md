# 麦麦留步 (followup_window) — 被 @ 后的跟进窗口（MaiBot 插件）

群聊中有人 @ 麦麦或引用回复后，开启一个短期的**跟进窗口**。在此期间，对话参与者后续不带 @ 的连续追问也能顺畅进入 Planner，由模型自主决定是否回复，同时不干扰群内其他闲聊。

---

### 背景与痛点

在群聊中，用户 @ 麦麦（或引用回复）并得到回答后，接下来的连续追问往往不再特意加上 @。

然而在 MaiBot 默认的动态门控模式（`reply_trigger_mode = "dynamic"`）下，门控偏偏在这时收得最紧：
- **额度被占满**：一次 @ 强制回复会扣减相当大的发言额度；
- **追问被拦截**：刚回复完后门控阈值大幅拉高，紧随其后且不带 @ 的追问极难进入 Planner。

结果就是：群友针对上一条回答继续追问，麦麦却因为门控阻拦而直接「装聋作哑」。

### 核心机制

本插件提供了一种克制、非侵入的跟进体验：

- **开窗记人**：有人 @ 麦麦或引用回复时开启活跃窗口（持续 `window_seconds`），记录对话参与者。
- **定向提频**：当参与者发送不带 @ 的追问（或任何人不带 @ 地引用麦麦）时，临时将该群的有效发言频率拉升至 `1.0`（约 5 秒），放行该批消息进入 Planner，由模型照常自主决定是否回复。
- **闲聊隔离**：其他群友之间的闲聊照常走原门控，不会因为处于活跃态而被放行。
- **受控续期**：窗口仅在麦麦自己发言、或再次被 @ / 引用时才续期，且设有总时长上限（`max_active_seconds`）；群友单纯发消息不续期，热闹的群绝不会一直处于活跃态。
- **纯粹非侵入**：仅检查「谁发的、是否 @ 或引用了麦麦」等元数据，**不读消息内容、不强制回复、不改写 Prompt**。

### 设计考量

- **为什么只认参与者？**  
  早期版本在窗口内放行每一批群消息，实测开窗后麦麦对群友之间的闲聊也频繁插话。窗口一旦全开，「与我有关」就只剩模型 Prompt 约束，随机性过大。按对话参与者筛选是**结构性约束**，不把克制赌在模型听话上。
- **为什么提频时一律拉到 1.0，而不是按倍数调高？**  
  动态门控对频率的反应是断崖式的：当频率低于某个阈值时，@ 之后剩余额度直接归零，调高倍数依然等于没调；若设在中间值，放行哪一批又依赖概率排序，不带问号、不带名字的追问恰好排在后面被淘汰。  
  因此，克制应当靠**时长控制**（窗口时长与活跃上限可按群覆盖）与**名单**，而非降低提频数值。

---

## 行为规则

- **触发开窗**：有人 @ 麦麦，或引用回复麦麦的消息 → 该群（在生效范围内时）进入活跃态，持续 `window_seconds`，发消息的人记录为参与者。  
  *叫名字、麦麦自己发言（包括主动插话、其他插件推送）均不开启窗口；私聊没有门控，不作处理。*
- **开窗不改常态频率**：开窗本身不改动群频率，宿主对 @ 本就强制回复，未参与者的消息照常走原门控。
- **追问临时提频**：活跃态内，参与者发来不带 @ 的消息，或任何人不带 @ 地引用回复麦麦 → 频率临时拉至 1.0，保持 5 秒后恢复；此期间若又有同类消息到来，自新消息起重新计时 5 秒。
- **参与者动态追加**：活跃态内有其他人 @ 或引用回复麦麦 → 该用户自动追加进参与者名单。
- **受控续期机制**：活跃态内麦麦成功发出消息，或再次被 @ / 引用回复 → 截止时间重设为「当前时间 + `window_seconds`」，但累计不得超过「本次活跃态开始时间 + `max_active_seconds`」。
- **退出与恢复**：窗口到期后约 1 秒内退出；正在提频的恢复调整系数为 1.0。插件卸载或被禁用时，所有活跃群立即恢复。
- **配置即时生效**：修改配置将某群移出范围（加入黑名单或移出白名单）时，该群已开窗口立即退出；修改时长仅影响后续的开窗与续期。
- **内存状态不持久化**：重启 MaiBot 后所有窗口状态清除，频率恢复为宿主默认。
- **特殊频率处理**：群被刻意静音（`talk_value == 0`）时不提频；群原始 `talk_value >= 1.0` 时无需提频。

## 安装

> [!NOTE]
> 运行环境要求：MaiBot 1.3.x、`maibot-plugin-sdk` 2.15.x–2.16.x。插件无额外 Python 依赖。

### 方式一：官方插件市场（推荐）

接入官方插件库后，在 MaiBot WebUI 的「插件扩展」中搜索 **麦麦留步**（或 `gsskk.followup-window`），点击安装即可。

### 方式二：手动安装

将本仓库克隆或复制到 MaiBot 的 `plugins/followup_window` 目录下：

```bash
git clone https://github.com/gsskk/maibot-plugin-followup /path/to/MaiBot/plugins/followup_window
```

然后在 WebUI 的插件配置页（或编辑 `plugins/followup_window/config.toml`）中把「启用插件」（`plugin.enabled`）设置为 `true`，并重启 MaiBot。  
*插件默认关闭，与 hermes_bridge 规范一致，需显式开启。*

## 配置说明

```toml
[plugin]
enabled = true

[followup]
scope_mode = "all"          # all | blacklist | whitelist
groups = []                 # blacklist 模式下关闭的群号，whitelist 模式下开启的群号；all 模式忽略
window_seconds = 300        # 被 @ 或麦麦发言后，活跃态持续时长（秒）
max_active_seconds = 900    # 一次活跃态自开启算起的最长硬上限（秒）

# 按群单独覆盖时长；留 0 或省略的项沿用上方默认值
[[followup.group_overrides]]
group_id = "123456789"
window_seconds = 120
max_active_seconds = 120    # 当等于 window_seconds 时表示不续期：窗口开一次 120 秒后必定退出
```

- **群号格式**：填写裸数字群号，不带平台前缀；加不加引号均可。
- **容错处理**：非法配置值不会导致配置失效。未知的 `scope_mode` 自动回落为 `all`，非正数的时长回落为默认值；`max_active_seconds` 若小于 `window_seconds` 则按 `window_seconds` 计算。异常项会在启用时以 `[followup] 配置问题:` 的 WARNING 级别打入日志。
- **低频群策略**：对于 `talk_value` 设定极低（如 0.01）的群，提频时同样会拉至 1.0。若不希望这类群接收追问，可通过配置缩短其窗口时长或加入黑名单。

## 验证与日志

插件所有运行日志均带有 `[followup]` 前缀，关键动作（进入、续期、提频、提频结束、退出）清晰可查：

```bash
grep '\[followup\]' /path/to/MaiBot/logs/<当天日志>
```

### 日志格式对照

| 日志示例 | 说明 |
| :--- | :--- |
| `[followup] 进入(@\|引用) 群 … 参与者=… 截止=… 上限=…` | 开启跟进窗口 |
| `[followup] 续期(发言\|@\|引用) 群 … 参与者=N 截止=… 已持续=…s` | 窗口续期 |
| `[followup] 提频(参与者\|引用) 群 … base=0.400 系数=2.500 至=…` | 追问到来，临时提频（`base` 为去掉插件调整后的原始 `talk_value`） |
| `[followup] 提频结束 群 … 系数=2.500→1.0` | 5 秒期满，调整系数恢复为 1.0 |
| `[followup] 退出(到期\|卸载\|禁用\|移出范围) 群 … 参与者=N 累计=…s` | 窗口正常退出或清理 |
| `[followup] … 写入系数未生效 … 放弃这次提频` | 偶见于重启后首条消息是不带 @ 的引用回复，宿主尚未建会话；约 4 秒内重试 5 次失败后放弃，下一条同类消息会再试 |
| `[followup] 群 … 恢复系数失败` | 恢复系数调用失败，每秒重试 1 次，12 次失败后放弃（此时系数可能偏高，直至下一次提频或重启） |

> [!NOTE]
> 宿主每次收到系数写入都会对当前待处理消息立即重算门控，因此在「提频」与「提频结束」（及每次写入重试）日志后紧跟一条门控判定属于正常现象，不代表有新消息到达。
> 
> **判定对照**：在宿主「回复调度 … 动态门控」日志中，参与者的追问批次判定应显示 `频率=1.000`、`阈值=0.00`、`判定=进入 Planner`；而同一窗口内其他群友的消息仍保持原频率（如 `频率=0.400`）正常判定。

## 已知限制

- **空闲退避（Backoff）仍生效**：Planner 若连续两次以「不回复」结束一轮，宿主群聊会进入 15 秒起步、指数倍增（上限 300 秒）的退避状态。该判定先于门控执行，因此活跃态下的首句反应可能延迟十几秒。
- **与其他调频插件冲突**：宿主每个会话的频率调整系数只有一个槽位（后写覆盖先写），若与其他调节发言频率的插件同时启用会相互覆盖。
- **只认参与者的权衡**：
  - 临时提频的 5 秒内，同一群中恰好到达的其他消息也会被放行；
  - 若 A @ 麦麦、B 接着不带 @ 追问同一话题，B 不在名单内仍走原门控，可能会被拦截；
  - 参与者在此期间与其他群友的闲聊也会被放行，由 Planner 自主决定是否接话。
- **退避延迟吞提频**：若空闲退避将参与者消息的判定推迟到了 5 秒提频结束之后，该批消息将按原始门控判定。
- **门控历史统计不清零**：活跃态期间产生的所有回复仍计入动态门控的 1 小时统计窗口内，窗口关闭后短期内的门控会比平时更紧。
- **focus_mode 专注模式**：开启时宿主有效频率本就恒为 1.0，本插件在其下无实际作用但完全无害。

## 更新

- **插件市场安装**：在 MaiBot WebUI 插件扩展页面点击「更新」。
- **手动安装**：在 `plugins/followup_window` 目录下执行 `git pull` 并重启 MaiBot，或重新复制仓库文件覆盖后重启。

可通过日志确认新版本加载成功（版本号与 `_manifest.json` 一致）：
```bash
grep '\[followup\] 已加载' /path/to/MaiBot/logs/<当天日志>
```

*插件源码目录默认不含 `config.toml`，更新或覆盖文件不会影响您已有的配置。*
