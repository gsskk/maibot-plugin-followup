# 麦麦留步 (followup_window) — 被 @ 后的跟进窗口（MaiBot 插件）

群聊中有人 @ 麦麦或引用回复后，给**这个人**开一个短期的**跟进窗口**。在此期间，他后续不带 @ 的追问会被当作「提到了麦麦」，一定进入 Planner，由模型自主决定是否回复，同时不干扰群内其他闲聊。

---

### 背景与痛点

在群聊中，用户 @ 麦麦（或引用回复）并得到回答后，接下来的连续追问往往不再特意加上 @。

然而在 MaiBot 群聊里，一条不带 @ 的消息要依次过三关才进得了 Planner：
- **消息防抖**：等一批消息收齐，通常几秒；
- **空闲退避**：Planner 连续两次选择不回复后，接下来十几秒到几分钟都不看新消息；
- **动态门控**：按发言频率和一小时内的回复额度决定放不放行，而一次 @ 强制回复会扣掉相当大的额度。

结果就是：群友针对上一条回答继续追问，麦麦却因为门控或退避直接「装聋作哑」。

### 核心机制

- **按人开窗**：有人 @ 麦麦或引用回复时，给这个人开一个窗口（持续 `window_seconds`）。每个人的窗口相互独立，各有自己的上限。
- **追问当作提及**：窗口开着的人发来任何消息（或任何人不带 @ 地引用麦麦），插件把这条消息标成「提到了麦麦」。宿主随即按提及处理：防抖缩短到 1 秒内、清零空闲退避、跳过频率门控，**这一批一定进入 Planner**，回不回仍由模型决定。
- **闲聊隔离**：窗口外的人的消息原样放行，照常走宿主门控。
- **受控续期**：自己再次 @ / 引用麦麦时续自己的期；麦麦在群里发言时，续**最近 `window_seconds` 内说过话**的参与者。群友单纯发消息不续期，每人都有总时长上限（`max_active_seconds`）。
- **不碰宿主状态**：只看「谁发的、是否 @ 或引用了麦麦」等元数据，不读消息内容、不改 Prompt、不调发言频率。停用、卸载、重启都无需清理。

### 设计考量

- **为什么不再调发言频率？**  
  旧版本（0.2.x）在追问到来时把群的发言频率临时拉到 1.0。但频率只作用于门控这一关，防抖和空闲退避会把追问的判定推迟到提频结束之后，追问依旧被漏掉；而且提频期间别人的消息也会被一起放行。标记「提及」走的是宿主为 @ 准备的现成通道，三关一次绕过，且只作用于这一条消息。
- **为什么只认参与者？**  
  早期版本在窗口内放行每一批群消息，实测开窗后麦麦对群友之间的闲聊也频繁插话。按对话参与者筛选是**结构性约束**，不把克制赌在模型听话上。
- **为什么 bot 发言只续最近说过话的人？**  
  否则麦麦和 B 聊得火热时，早已离开的 A 的窗口也会一直被续着，A 之后跟别人说的话都会被麦麦看一眼。

---

## 行为规则

- **触发开窗**：有人 @ 麦麦，或引用回复麦麦的消息 → （该群在生效范围内时）为这个人开窗，持续 `window_seconds`，上限为此刻起 `max_active_seconds`。  
  *叫名字、麦麦自己发言（包括主动插话、其他插件推送）均不开启窗口；私聊没有门控，不作处理。*
- **@ 消息不改写**：宿主对 @ 本就强制回复，插件只开窗 / 续期。
- **追问标记提及**：窗口开着的人发来不带 @ 的消息 → 标成提及，宿主强制进 Planner；任何人不带 @ 地引用回复麦麦 → 同样标记，并为他开窗或续期。追问本身不续期。
- **各人续期**：自己再次 @ / 引用麦麦 → 自己的截止时间重设为「当前 + `window_seconds`」，不超过自己的上限；不影响别人的窗口。
- **麦麦发言续期**：麦麦在该群成功发出消息 → 该群里最近 `window_seconds` 内说过话、窗口还开着的人各自续期（同样不超过各自上限）。因此一个人最长约在他最后一次说话后 2 × `window_seconds` 失效。
- **到期**：截止时间一过窗口即失效；之后此人再 @ 才会重新开窗，新的上限从那时算起。
- **配置即时生效**：修改配置将某群移出范围（加入黑名单或移出白名单）时，该群的窗口立即关闭；关闭插件时清空所有窗口；修改时长仅影响后续的开窗与续期。
- **内存状态不持久化**：重启 MaiBot 后所有窗口清除。

### 例子

`window_seconds = 300`、`max_active_seconds = 900`：

| 时间 | 发生了什么 | A 的窗口 | B 的窗口 |
|---|---|---|---|
| 20:00 | A @ 麦麦 | 开窗，到 20:05，上限 20:15 | — |
| 20:02 | B @ 麦麦 | 不变 | 开窗，到 20:07，上限 20:17 |
| 20:02:10 | 麦麦回 B | 续到 20:07:10 | 续到 20:07:10 |
| 20:04 | A 不带 @ 追问 | 标记提及，麦麦一定看到 | |
| 20:04:10 | 麦麦回 A | 续到 20:09:10 | 续到 20:09:10 |
| 20:05 | 路人 C 插话 | 原样放行，走门控 | |
| 20:06 起 | 麦麦一直和 B 聊，A 不再说话 | 20:09 前麦麦的发言仍会续 A（A 20:04 说过话）；之后不再续，最后约在 20:14 关闭 | 每次都续，到上限 20:17 关闭 |

## 安装

> [!NOTE]
> 运行环境要求：MaiBot 1.3.13 及以上的 1.3.x、`maibot-plugin-sdk` 2.16.x–2.19.x。插件无额外 Python 依赖。

### 方式一：官方插件市场（推荐）

接入官方插件库后，在 MaiBot WebUI 的「插件扩展」中搜索 **麦麦留步**（或 `gsskk.followup-window`），点击安装即可。

### 方式二：手动安装

将本仓库克隆或复制到 MaiBot 的 `plugins/followup_window` 目录下：

```bash
git clone https://github.com/gsskk/maibot-plugin-followup /path/to/MaiBot/plugins/followup_window
```

然后在 WebUI 的插件配置页（或编辑 `plugins/followup_window/config.toml`）中把「启用插件」（`plugin.enabled`）设置为 `true`，并重启 MaiBot。  
*插件默认关闭，与 hermes_bridge 规范一致，需显式开启。*

## 配置说明

```toml
[plugin]
enabled = true

[followup]
scope_mode = "all"          # all | blacklist | whitelist
groups = []                 # blacklist 模式下关闭的群号，whitelist 模式下开启的群号；all 模式忽略
window_seconds = 300        # 每人的窗口时长（秒）；也是「最近说过话」的判定范围
max_active_seconds = 900    # 每人一次窗口自开启算起的最长硬上限（秒）

# 按群单独覆盖时长；留 0 或省略的项沿用上方默认值
[[followup.group_overrides]]
group_id = "123456789"
window_seconds = 120
max_active_seconds = 120    # 当等于 window_seconds 时表示不续期：窗口开一次 120 秒后必定关闭
```

- **群号格式**：填写裸数字群号，不带平台前缀；加不加引号均可。
- **容错处理**：非法配置值不会导致配置失效。未知的 `scope_mode` 自动回落为 `all`，非正数的时长回落为默认值；`max_active_seconds` 若小于 `window_seconds` 则按 `window_seconds` 计算。异常项会在启用时以 `[followup] 配置问题:` 的 WARNING 级别打入日志。
- **宿主开关**：标记的效果依赖宿主配置 `chat.reply_timing.mentioned_bot_reply = true`（默认开启）。关掉它，被标记的追问只会缩短防抖，不再强制进 Planner。

## 验证与日志

插件所有运行日志均带有 `[followup]` 前缀：

```bash
grep '\[followup\]' /path/to/MaiBot/logs/<当天日志>
```

### 日志格式对照

| 日志示例 | 说明 |
| :--- | :--- |
| `[followup] 开窗(@\|引用) 群 … <用户> 截止=… 上限=…` | 为此人开启跟进窗口 |
| `[followup] 续期(@\|引用) 群 … <用户> 截止=… 上限=…` | 此人再次 @ / 引用，续自己的期 |
| `[followup] 续期(发言) 群 … <用户>→<截止> …` | 麦麦发言，续最近说过话的人 |
| `[followup] 标记提及(追问\|引用) 群 … <用户> 消息=…` | 这条消息被标成提及 |
| `[followup] 到期 群 … <用户> 截止=… 累计=…s` | 窗口过期（在下一次该群有消息或麦麦发言时记录） |
| `[followup] 群 … 移出范围,关闭其中的窗口` | 配置变更后清理 |

> [!NOTE]
> **判定对照**：被标记的消息在宿主日志里会紧跟一条「检测到提及消息，下一轮 Planner 将强制触发；消息编号=…」（消息编号与插件日志一致），随后「回复调度 … 调度=强制触发」。同一时段其他群友的消息仍是「动态门控 … 频率=<原值>」。

## 已知限制

- **参与者的闲聊也会被看一眼**：窗口内参与者跟别人说的话同样会强制进 Planner，由模型决定是否接话。
- **非参与者接话**：若 A @ 麦麦、B 接着不带 @ 追问同一话题，B 不在名单内仍走原门控，可能会被拦截。
- **门控额度**：强制触发会计入动态门控的回复额度，窗口结束后该群短期内会比平时更安静。
- **阻塞钩子**：入站钩子需要等插件返回，宿主才继续处理消息。插件对绝大多数消息不做任何调用即返回；唯一的远程调用是判断「引用的是不是麦麦」（超时 1.5 秒），整个钩子 3 秒超时，超时则宿主按原消息继续。

## 更新

- **插件市场安装**：在 MaiBot WebUI 插件扩展页面点击「更新」。
- **手动安装**：在 `plugins/followup_window` 目录下执行 `git pull` 并重启 MaiBot，或重新复制仓库文件覆盖后重启。

可通过日志确认新版本加载成功（版本号与 `_manifest.json` 一致）：
```bash
grep '\[followup\] 已加载' /path/to/MaiBot/logs/<当天日志>
```

*插件源码目录默认不含 `config.toml`，更新或覆盖文件不会影响您已有的配置。*
